# Практикумы для лектора — методичка проведения пар (недели 2, 3, 6)

Сценарии практической части пар: тайминг, подготовка, поминутный ход, живое демо и команды
`ape`, чекпоинты-обходы, типовые ошибки студентов и реакция, критерий «сделано на паре»,
планы Б (если мало/много времени).

**Общая подготовка (один раз в начале потока):**
- Проверь, что у всех прошёл онбординг Лекции 1: `ape` установлен, `/login` работает, `ape usage` показывает квоту.
- Держи наготове свой экран с `ape` для живого демо (шрифт крупный, тёмная тема).
- Скиллы недели включаются `/skills` — проверь, что они есть в наборе группы.
- На каждой паре напоминай: cost виден в `ape usage` — это привычка с первой недели.

**Практикум Evals (`w3l4`, 17.09)** — уже расписан отдельно: см.
[`2026-09-17-evals-qwen-judge.md`](2026-09-17-evals-qwen-judge.md) (часть III + «Заметки лектору»).

## w2l1 — JTBD, ICP и шорт-лист идей · воркшоп 40 мин

**Цель пары:** у каждого студента заполнена ICP-канва одной идеи и проверена соседом.

**Подготовить:** шаблон ICP-канвы (`docs/templates/`) открыт у всех; пример хорошей и плохой канвы на слайде.

**Ход (40 мин):**
| Время | Что делает лектор | Что делают студенты |
|---|---|---|
| 0–3 | Раздаёшь шаблон, ставишь таймер 15 мин | Выбирают 1 идею из 3 |
| 3–18 | Ходишь по рядам (чекпоинт 1) | Заполняют ICP-канву через `icp-interviewer` |
| 18–28 | Объявляешь обмен в парах | Отдают канву соседу, тот задаёт 1 беспощадный вопрос |
| 28–38 | Модерируешь 2–3 разбора вслух | Чинят слабое место канвы |
| 38–40 | Фиксируешь домашку (шорт-лист 3 идей) | — |

**Живое демо (перед воркшопом, 3 мин):**
```
/skills                      → icp-interviewer: Y
ape ask "по идее <одна строка> задай мне вопросы icp-interviewer и собери ICP-канву на 1 страницу"
```
Покажи, что скилл САМ переспрашивает про триггер/костыль/успех — халтуру не пропускает.

**Чекпоинт 1 (обход 3–18):** у каждого в поле «Кто» — конкретный человек, не «все X». Если видишь «студенты/предприниматели» — останови, попроси имя и контекст.

**Типовые ошибки → реакция:**
- «ICP = сегмент рынка» → «назови одного человека, которого позовёшь на тест».
- JTBD-тавтология («хочу AI-ассистента, чтобы помогал») → верни к формуле Когда/Хочу/Чтобы, убрать решение из формулировки.
- Нет готовности платить → «во сколько часов/₽ ему обходится текущий костыль?».

**Сделано на паре:** ≥1 ICP-канва заполнена, прошла беспощадный вопрос, слабое место починено.

**План Б:** мало времени — обмен в парах вместо 3 разборов вслух; много времени — второй проход по второй идее.

## w2l2 — Reverse JTBD · групповое упражнение

**Цель пары:** группа умеет восстанавливать ICP+JTBD готового продукта и переносит приём на конкурента своей идеи.

**Подготовить:** разбить на группы по 3; закрепить за каждой 1 продукт (Cursor / Perplexity / Granola / NotebookLM / Replit).

**Ход (~40 мин):**
| Время | Лектор | Студенты |
|---|---|---|
| 0–3 | Раздаёшь продукты по группам, даёшь метод (5 вопросов) | — |
| 3–13 | Обход (чекпоинт) | Восстанавливают ICP + JTBD своего продукта в `ape` |
| 13–28 | Модерируешь «защиту» групп | Защищают перед соседней группой; та ищет натяжки |
| 28–38 | Сводишь паттерны победителей на доску | Сравнивают со своей идеей |
| 38–40 | Домашка: reverse конкурента своей идеи | — |

**Команды `ape`:**
```
ape ask "сделай reverse-JTBD для <продукт>: восстанови ICP (один человек), JTBD по формуле
  Когда/Хочу/Чтобы, что он заменил и чем отличается. без маркетинга, по фактам о продукте"
/save cloud discovery/reverse-jtbd.md
```

**Чекпоинт (3–13):** у группы есть триггер («когда открывает») и замена («что делал до») — без них reverse не сделан.

**Типовые ошибки → реакция:**
- Пересказ лендинга вместо работы → «в какой момент жизни человек его открывает?».
- «AI внутри» как ценность → «а какую работу это закрывает, чего не было раньше?».
- Слишком широкий ICP → сузить до одного человека, как в w2l1.

**Сделано на паре:** каждая группа назвала ICP+JTBD+замену своего продукта и 1 паттерн, которого нет у своей идеи.

**План Б:** мало времени — по 1 продукту на группу без перекрёстной защиты; много — вторая итерация с другим продуктом.

## w3l1 — AI-native discovery · симуляция интервью (30 мин)

**Цель пары:** каждый прогнал симуляцию интервью со своей ICP, прожал идею адвокатом дьявола, записал первую строку cost-журнала.

**Подготовить:** у студентов под рукой ICP-канва из w2l1 (вставляется в промпт целиком).

**Ход (30 мин):**
| Время | Лектор | Студенты |
|---|---|---|
| 0–3 | Показываешь шаблон сим-интервью, включаешь `research` | — |
| 3–15 | Обход (чекпоинт 1) | Гоняют 10 вопросов симуляции со своей ICP |
| 15–24 | Объясняешь анти-эхо-камеру | Прогоняют идею через `devils-advocate`, выписывают 3 слабых места |
| 24–29 | `ape usage` — первая запись cost | Записывают токены/₽ в decision.md |
| 29–30 | Домашка: живое интервью нед. 3→4 | — |

**Команды `ape`:**
```
ape ask "Ты — <описание из ICP-канвы целиком>. Ты НЕ AI-ассистент, ты этот человек.
  Отвечай как он: со своими сомнениями, ленью, отмазками. Не угождай интервьюеру.
  Я — исследователь, задам 10 вопросов про <область>. Готов?"

ape ask "ты VC, отказавший 100 таким стартапам. запрещены слова great/amazing/потенциал.
  если идея слабая — скажи прямо, каждое утверждение с аргументом. идея: <моя>"

ape usage
```

**Чекпоинт 1 (3–15):** персонаж НЕ поддакивает. Если «пользователь» слишком удобный — это эхо-камера; попроси усилить «не угождай интервьюеру / со своими отмазками».

**Типовые ошибки → реакция:**
- Симуляцию принимают за истину → напомни: это тренажёр гайда, истина — живое интервью.
- `devils-advocate` всё равно хвалит → усилить запрет слов и «без бесплатных похвал».
- Забыли записать cost → `ape usage` до и после, разница в decision.md.

**Сделано на паре:** прогон симуляции + 3 выписанных слабых места + первая запись cost.

**Ключевой акцент вслух:** уверенность модели ≠ истинность. Симуляция готовит к живому, не заменяет его.

**План Б:** мало времени — симуляция дома, на паре только `devils-advocate` + cost.

## w3l2 — Выбор архитектуры: workflow vs agent (30 мин)

**Цель пары:** каждый обосновал архитектуру своей идеи по 5 критериям (заготовка для КТ1/ADR).

**Подготовить:** `architecture-chooser` включён; чек-лист 5 критериев на слайде.

**Ход (30 мин):**
| Время | Лектор | Студенты |
|---|---|---|
| 0–3 | Напоминаешь 3 архитектуры и decision tree | — |
| 3–15 | Обход (чекпоинт) | Гоняют 3 идеи через `architecture-chooser` |
| 15–25 | Разбираешь 2–3 пограничных случая вслух | Заполняют чек-лист 5 критериев для выбранной |
| 25–30 | Связь со стоимостью (агент = ×3–5) | Пишут решение одним абзацем с обоснованием |

**Команды `ape`:**
```
/skills → architecture-chooser: Y
ape ask "по описанию задачи помоги выбрать workflow/agent/hybrid. задай вопросы по 5 критериям
  (регулярность, цена ошибки, креативность, частота смены логики, compliance). дай рекомендацию
  с обоснованием по каждому. если 50/50 — назови и объясни trade-off. задача: <моя идея>"
```

**Чекпоинт (3–15):** каждый критерий имеет ответ, а не «наверное агент». Пограничный случай — норм, если назван честно.

**Типовые ошибки → реакция:**
- «Агент, потому что модно» → прогоните по 5 критериям; часто выходит workflow.
- Игнор стоимости → напомни: агент = токены × шаги, ×3–5 к workflow (мост к неделе 5).
- Жёсткий workflow на вариативный вход → предложи гибрид или дать агенту решать шаг.

**Сделано на паре:** решение workflow/agent/hybrid + обоснование по 5 критериям (идёт в decision.md к КТ1).

**Мост:** решение определит шаблон design-doc на неделе 4 (workflow→MLSDD, agent→Agent Design).

**План Б:** мало времени — только выбранная идея; много — прогнать все 3 и сравнить.

## w6l1 — Анатомия агента · сборка каркаса (2 практики по 45 мин)

**Цель пары:** у каждого есть схема анатомии агента и запущен каркас (loop + tools + structured output), данные подаются как canonical JSON.

**Подготовить:** `/data` работает (проверь `data_query` на демо-сущности); пример Data-recipe открыт.

### Практика 1 (45 мин) — анатомия на бумаге
| Время | Лектор | Студенты |
|---|---|---|
| 0–5 | Показываешь схему 8 компонентов | — |
| 5–35 | Обход (чекпоинт 1) | Заполняют анатомию своего агента на 1 стр + выбирают паттерн |
| 35–45 | Разбор 2–3 анатомий вслух | Правят условие остановки и границы tools |

### Практика 2 (45 мин) — данные + каркас
| Время | Лектор | Студенты |
|---|---|---|
| 0–10 | Живое демо `/data` (источник→canonical JSON) | — |
| 10–40 | Обход (чекпоинт 2) | Пишут Data-recipe + каркас агента через `ape code` |
| 40–45 | Ставишь ДЗ (dz-agent-anatomy.md) | Фиксируют, что осталось доделать дома |

**Команды `ape`:**
```
/data new <entity>        # рецепт источник→canonical JSON
/data run <entity>        # применить (schema/provenance/ttl)
/data query <entity> <фильтр>
ape code "собери агента для <задача>: loop с условием остановки и лимитом шагов, 2 tools
  (один — data_query), structured output по JSON-схеме, простая память. чистый FastMCP-клиент"
```

**Чекпоинт 1 (анатомия):** у loop есть **условие остановки** и **лимит шагов**; structured output — по схеме, не свободный текст.

**Чекпоинт 2 (данные):** агент берёт данные через `data_query`, а НЕ читает сырой PDF/CSV. Это половина оценки ДЗ.

**Типовые ошибки → реакция:**
- «Агент» = `while True` без остановки → добавь условие и лимит шагов (иначе жжёт токены).
- Свободный текст вместо structured output → JSON-схема, парсинг без regex.
- Агент ест сырьё → напомни главный тезис: агент ≠ человек, данным нужны типы/схема/provenance/ttl.
- Multi-agent «для солидности» → простейший паттерн (ReAct), если задача не дробится на роли.

**Сделано на паре:** схема анатомии + запущенный каркас + 1 Data-recipe; остальное — в ДЗ
([`dz-agent-anatomy.md`](dz-agent-anatomy.md)), идёт в допуск к КТ2.

**План Б:** мало времени — каркас агента переносится в ДЗ, на паре только анатомия + Data-recipe.
