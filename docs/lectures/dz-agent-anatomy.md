# ДЗ — Разработка агента (после лекции «Анатомия агента»)

> **К лекции:** `w6l1` «Анатомия агента: точка входа» · **Сдать:** к следующей паре (`w6l2`), PR в свой репозиторий · **Вес:** практика-допуск к КТ2 (анатомия агента = 10 баллов рубрики КТ2)

## Цель

Собрать **минимального, но честного агента** своего pet-проекта: не «промпт в цикле», а агент с явной анатомией, управляемым loop и **правильно поданными данными**. Это стартовая точка разработки — дальше (недели 7–8) добавим тесты, роли sub-agent'ов, память и cost-контроли.

Главный акцент задания: **агент — не человек**. Половина оценки — за то, что данные приходят агенту как canonical typed JSON (через Data Plane), а не сырым файлом.

---

## Что сдать (структура в репозитории)

```
agent/
  README.md          # схема анатомии + выбранный паттерн + как запустить
  agent.py           # loop + tools + memory + structured output
  recipe/<entity>.json   # Data-recipe: источник → canonical JSON
  NOTES.md           # «где агент ≠ человек в моих данных» (5 строк)
```

### 1. Анатомия (README.md) — схема на 1 страницу
Разложи своего агента по 8 компонентам (по Шевченко) — по строке на каждый, конкретно под свой домен:

| Компонент | Что заполнить |
|---|---|
| Agent Core | какая модель/профиль (`code` → Qwen / `ask` → DeepSeek) и почему |
| System Prompt | роль, запреты, формат (одной фразой; полностью — в w6l2) |
| User Prompt | что подаётся на вход в реальном сценарии |
| Agent Loop | как выглядит шаг и **условие остановки** |
| Tools | ≥2 инструмента: имя, что делает, вход/выход |
| Memory | что помнит между шагами (или «пока нет, обоснуй») |
| Sub-agents | нужны ли (defer-принцип: не тяни, если рано) |
| Structured Output | JSON-схема ответа |

### 2. Выбор паттерна + обоснование
Назови паттерн (ReAct / Planner-Executor / Reflection / Router / Multi-agent) и объясни в 3–5 строк, **почему он, а не проще**. Правило курса: берём простейший паттерн, решающий задачу.

### 3. Код (agent.py) — минимально рабочий
- **Agent loop** с явным **условием остановки** и **лимитом шагов** (предохранитель от зацикливания).
- **≥2 tools** (через курсовой MCP; один из них — `data_query`).
- **Structured output** — ответ по JSON-схеме, не свободный текст (парсится без regex).
- **Memory** — хотя бы простая (что перенести на следующий шаг) или явное обоснование, почему пока не нужна.
- Каждый вызов LLM метрится (cost в журнале виден через `ape usage`).

### 4. Данные (обязательная половина задания)
- **1 Data-recipe** `recipe/<entity>.json`: источник (`csv|json|http|sqlite`) → `map+cast` → `rules (assert/pii_mask)` → canonical JSONL со **схемой, provenance, ttl**.
- **Схема сущности**: обязательные поля с типами (числа — числа, даты — даты, деньги — money).
- Агент берёт данные **тулом `data_query`**, а не читает сырой файл.
- **NOTES.md (5 строк):** где именно в твоих данных агент ≠ человек — что человек «дочитал бы», а агенту пришлось задать явно (единицы, свежесть, неоднозначность, объём).

## Как делать в ape

```bash
# 1) данные → canonical JSON
/data new <entity>            # шаблон рецепта ~/.ape/recipes/<entity>.json
# отредактируй рецепт: source → map/cast → rules → emit
/data run <entity>            # применить: источник → canonical JSONL (schema/provenance/ttl)
/data schema <entity>         # проверить контракт полей
/data query <entity> <фильтр> # прочитать чистые свежие данные

# 2) каркас агента
ape code "собери агента для <задача>: agent loop с условием остановки и лимитом
  шагов, 2 инструмента (один — data_query), structured output по JSON-схеме,
  простая память между шагами. без внешних фреймворков, чистый FastMCP-клиент"

# 3) проверка расхода
ape usage
```

> Профиль `code` (self-host Qwen) — для кода агента; данные готовит Data Plane. Если задача дробится на роли — посмотри `/agents` (мульти-агенты), но для этого ДЗ обычно достаточно одного агента.

## Definition of Done

- [ ] Схема анатомии из 8 компонентов заполнена под свой домен (не плейсхолдеры).
- [ ] Паттерн выбран и обоснован (почему он, а не проще).
- [ ] `agent.py` запускается; есть loop, **условие остановки** и **лимит шагов**.
- [ ] ≥2 tools, один из них — `data_query`; ответ — **structured output** по схеме.
- [ ] Есть Data-recipe: источник → canonical JSON со схемой, provenance, ttl.
- [ ] Агент читает данные через `data_query`, а не сырой файл.
- [ ] NOTES.md: 5 строк «где агент ≠ человек в моих данных».
- [ ] Виден cost прогона (`ape usage`).

## Критерии оценки (10 баллов, идут в допуск к КТ2)

| Критерий | Балл |
|---|---|
| Анатомия полная и конкретная | 2 |
| Паттерн выбран осознанно (простейший достаточный) | 1 |
| Loop с условием остановки и лимитом шагов | 2 |
| ≥2 tools + structured output по схеме | 2 |
| Data-recipe: canonical JSON со схемой/provenance/ttl | 2 |
| NOTES.md: понимание «агент ≠ человек» | 1 |

## Частые ошибки (снимут баллы)

- «Агент» = один промпт в `while True` без условия остановки → зацикливание.
- Свободный текст вместо structured output → нельзя надёжно распарсить.
- Агент читает сырой PDF/CSV «как есть» → нарушен принцип данных для агента.
- Multi-agent «для солидности» там, где хватает ReAct → лишняя сложность и cost.
- Данные без provenance/ttl → нельзя проверить, откуда и насколько свежо.
