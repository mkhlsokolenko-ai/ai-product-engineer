Сравнение нашего **AI Product Engineer** с курсом CMU 11-768 (Graham Neubig / Daniel Fried) и план интеграции трёх модулей. Источник: [cmu-agents.com](https://www.cmu-agents.com/) + разбор программы.

## 2. Что берём (решение зафиксировано)

Из четырёх кандидатов взяли **три** (Sandboxing отложен — частично закрыт неделями 8–9: границы/auth/threat-model):

### Модуль A. Evals — усилить до планки CMU
- **Что было:** сильная неделя 11 (три грейдера, RAG-метрики, prompt versioning), скилл `eval-generator`, `run_eval.py`, промпт-судья.
- **Разрыв vs CMU:** eval у них — **ранний навык на песочнице** (2-е занятие), а не поздний QA; есть **trajectory/outcome-грейдеры** (SWE-bench `FAIL_TO_PASS`); судья гоняется постоянно.
- **Что добавляем:**
  1. **Ранняя eval-лаборатория на неделе 3** на готовом `coffee-reviews-agent` (песочница) — новая лекция `w3l4`, файл `docs/lectures/2026-09-17-evals-qwen-judge.md`. Пилот — 17.09.2026.
  2. **Судья на self-host Qwen** (profile `code`, марж. стоимость ≈ 0) вместо только DeepSeek → eval на каждом коммите, majority-vote бесплатно, без egress.
  3. **Outcome/trajectory-грейдер** в датасете (мерим факт исхода, не «красоту ответа»).
- **Где в программе:** новая `w3l4` (foundational) + обновлённые `w11l1/w11l2` (ссылка на Qwen-судью и trajectory-eval).

### Модуль B. Observability & Cost — довести до product-grade
- **Что было:** `w10l1` (logs/metrics/traces, поверхностно), `w8l3` (latency/cost controls), тайл «Наблюдаемость: Langfuse — скоро».
- **Разрыв vs CMU:** у них трассировка **траекторий агента** (Laminar/MLflow), экономика контекста (KV-cache pricing), стоимость **на задачу**, а не на вызов.
- **Что добавляем:** в `w10l1` — трейс полной траектории (шаги/tool-calls), **cost-per-task** и деградация; связка с cost-журналом FastMCP (`prompt_version` уже пишется). Тайл в портале: `Langfuse — скоро` → наш трейс-журнал.
- **Где в программе:** усилённая `w10l1` + врезка в `w8l3`.

### Модуль C. SFT на траекториях — по-настоящему новое ⭐
- **Что было:** ничего. Это самый большой разрыв.
- **Почему нам это доступно (а большинству курсов нет):** есть self-host Qwen (Vast L40 FP8) + память `ape` (успешные траектории агентов). Петля продукт → данные → модель.
- **Что добавляем:** новая лекция **«Дистилляция удачных траекторий → LoRA fine-tune Qwen»** — как из логов `ape`/Blackboard собрать SFT-датасет (вход, инструменты, успешный исход по eval-грейдеру), запустить LoRA на нашем боксе, замерить до/после **тем же eval из модуля A**. RL/GRPO даём обзорно («что дальше»), без практики.
- **Где в программе:** новая лекция в Блоке 4 (после недели 11 — сначала научились мерить, потом дообучать по метрике). Кандидат — `w11l3` (bonus/advanced-трек) либо расширение недели 12.

## 3. Порядок как у CMU: мерить → потом дообучать

CMU-последовательность *harness → eval → train* мы отражаем так: `w3l4` (научился мерить на песочнице) → неделя 10 (наблюдаемость MVP) → неделя 11 (мерить свой проект) → SFT-лекция (дообучить по метрике). SFT **опирается на eval-грейдер** из модуля A как на функцию награды/критерий отбора траекторий — без модуля A модуль C бессмыслен.

## 5. Что НЕ берём и почему

- **RL/GRPO как практика** — избыточно для продуктового курса и дорого по GPU. Даём обзор в SFT-лекции.
- **Отдельный модуль Sandboxing** — уже покрыт неделями 8–9 (границы системы, auth-ландшафт, threat model, whitelist tools, human-in-the-loop). Возьмём отдельным блоком, только если появится агент с реальным code-execution.
- **GUI-агенты, tree search, reranking/critic** (домены CMU) — за рамками продуктового фокуса; reranking частично уже есть в RAG-неделе (нед. 9).
