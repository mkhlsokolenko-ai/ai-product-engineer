# Портал курса (AiEngineer.ai) — план

Единый веб-портал курса: вход, админка расходов, лидерборд, план и прогресс,
оценки/успеваемость, проекты студентов с документами. Дизайн — как у **red-team.tech**.

> Статус: план. Домен покупается, бокс поднимается позже. Здесь — архитектура,
> чтобы фронт/бек собирать по ней.

## Ключевая мысль: половина данных уже есть

Портал **не требует новой БД под расходы** — он читает то, что MCP уже пишет:

- **`cost_journal` (Postgres)** → админка расходов, лидерборд, личный кабинет, графики
  сжигания токенов. Всё уже метрится на каждый вызов (студент, сессия, модель, стоимость).
- **Квоты (5M/сессия, 5/нед, 25M/нед)** → прогресс-бары остатка.
- **MinIO/S3** → хранилище документов проектов (см. storage ниже).
- Прогресс/оценки/план — новые таблицы (`students`, `projects`, `grades`, `milestones`).

## Страницы

| Страница | Источник данных | Роль |
|---|---|---|
| Логин (SSO) | Keycloak (тот же realm) | все |
| Личный кабинет | cost_journal + квоты | студент |
| Расход токенов (админка) | cost_journal (агрегаты) | лектор |
| Лидерборд | cost_journal + grades | все |
| План курса и «как идёт» | milestones + прогресс | все |
| Оценки / успеваемость | grades, submissions | лектор ставит, студент видит |
| Проекты + документы | projects + MinIO (upload) | студент добавляет, лектор смотрит |

## Стек

```
Next.js (фронт, дизайн red-team.tech)
   │  Keycloak SSO (тот же realm ai-product-engineer) — вход, роли student/lecturer
   ▼
Portal API (FastAPI)  ──►  Postgres (cost_journal + новые таблицы)
   │                   ──►  MinIO / S3 (документы проектов, presigned URL)
   └── переиспользует ту же БД, что и MCP (единый учёт)
```

- **Keycloak на фронте** — да: тот же realm, что у MCP. Один вход и в портал, и в шлюз
  (SSO). Роль `lecturer` открывает админку и оценки.
- **Portal API** — отдельный FastAPI-сервис (не мешаем MCP-протокол и REST для UI).
  Читает cost_journal напрямую, пишет grades/projects/milestones.
- **Загрузка документов** — presigned URL в MinIO; после загрузки триггерит ingest
  (OCR → chunk → embed → Qdrant), чтобы документ сразу попадал в RAG проекта.

## Хранилище (решение по S3)

**Рекомендация: MinIO на server-1** (S3-совместимый, self-hosted):
- ФЗ-152: данные не уходят из РФ-контура (важно и для корпоративного bootcamp).
- Presigned URL, бакет `projects/<студент>/`, лимит ~2 ГБ/студента.
- Нет egress-платы; том снапшотится для бэкапа.
- Позже при росте — можно переключить на облачный S3 (тот же API, минимум правок).

Альтернатива — облачный S3, если не хочется держать хранилище на пилоте. Но для старта
MinIO рядом с Qdrant/Postgres проще и дешевле.

## OCR / быстрые инструменты (отдельный сервис)

Тяжёлый парсинг документов выносим в **отдельный сервис `tools`** (OCR, извлечение
текста), подключённый к тому же MCP как набор инструментов (`ocr`, `extract_text`):

- **Зачем отдельно:** OCR CPU-bound, не должен конкурировать с MCP/Postgres; масштабируется
  независимо; ingest-пайплайн (док → OCR → chunk → embed → Qdrant) естественно живёт тут.
- **Нужен ли отдельный физический сервер:** на старте — нет, хватит контейнера на server-1
  или на GPU-боксе. Отдельный сервер — когда объём загрузок вырастет.
- **Инструмент:** Tesseract — базовый; для RU-документов часто лучше **PaddleOCR / docTR**.
- **Важный нюанс:** Qwen3.8-27B — сам **VLM**, читает изображения. Для многих сканов
  отдельный OCR не нужен — модель извлекает текст напрямую. Выделенный OCR оправдан для
  **массового/дешёвого** извлечения текста, где гонять VLM дорого. То есть: VLM для сложных
  документов, Tesseract/Paddle для bulk — а роутинг между ними прячем за MCP-tool.

## Порядок сборки (когда домен куплен)

1. DNS AiEngineer.ai → бокс; Keycloak realm (уже нужен для MCP).
2. MinIO на server-1 + бакеты + ingest-хук.
3. Portal API (FastAPI): чтение cost_journal, таблицы grades/projects/milestones.
4. Next.js фронт (дизайн red-team.tech) + Keycloak SSO.
5. Сервис `tools` (OCR) как MCP-инструменты; подключить к ingest.
