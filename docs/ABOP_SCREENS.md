# ABOP — Экранная раскладка для прототипа

**Назначение:** пошаговая раскладка каждого экрана среды ABOP, чтобы дизайнер отрисовал **точные мокапы и кликабельный прототип**. Для каждого экрана: зоны layout, компоненты (из UI-kit), состояния (пустой/загрузка/ошибка), и **кликабельность** (что нажимается → куда ведёт).
**Связка:** токены и компоненты — `ABOP_DESIGN_KIT.md`; продукт/вкладки/FR — `ABOP_PRD.md` v1.1; бренд/маскот/спиннеры — `docs/brand/`.
**Референс структуры:** LUDA MIRA v3 (сетка, вкладки-маршрут, паттерны экранов — переиспользуем, перекрашиваем в бренд ABOP).
**Статус:** v1.1. Приоритет отрисовки: **MVP = §3 Пульт → §4 Навыки → §5 Данные**, затем §2/§6/§7/§8, затем **§8а Эксплуатация/Флот** (надстраивается над рабочим одиночным прогоном).

Легенда зон: `▓` акцент/активное · `░` вторичное/стекло · `·` мета/mono · `[ ]` интерактив.

│              │                                                            │
│  МАРШРУТ:    │                                                            │
│  [Обзор]     │                                                            │
│  [Канва]     │                                                            │
│  [Данные]    │                                                            │
│  [Навыки]    │                                                            │
│  [Прогоны]•3 │  ← бейдж = активные прогоны / HITL в очереди               │
│  [Эксплуат.]•5│ ← бейдж = живые экземпляры флота (крит-точка при ошибке)  │
│  [Паспорт]   │                                                            │
│  [Настройки] │                                                            │
│              │                                                            │
│  ─────────   │                                                            │
│  🐵 Эйп      │  ← маскот-статус текущего прогона (idle/думает/HITL/…)     │
│  «думает»    │                                                            │
│  @user·роль  │                                                            │
└──────────────┴──────────────────────────────────────────────────────────┘
```
- **Sidebar** (240px, стекло на градиенте): лого-конверт вверху; вертикальный маршрут вкладок (активная — индиго-подсветка + левый бордер `--brand`); бейджи-счётчики (Прогоны•N, **Эксплуатация•N** = живые экземпляры флота, крит-точка при ошибке/дрейфе, Паспорт при нарушении конверта — амбер/крит точка); внизу **маскот Эйп** отражает статус активного прогона + пользователь/роль.
- **Topbar**: крошки маршрута слева; `⌘K`-палитра (поиск по навыкам/агентам/прогонам); справа — переключатель темы (dark по умолчанию) и индикатор расхода (`cost_journal`: токены/₽ + остаток недельной квоты).
- **Темы:** dark-first (основная), light — по образцу двухтемности LUDA. Все состояния рисовать в обеих.
- **Адаптив:** ≥1280 полный; 1024 — sidebar сворачивается в иконки; <768 не приоритет (среда разработки — десктоп).

**Кликабельность каркаса:** каждый пункт маршрута → свой экран (§2–§8а); лого → Обзор; `⌘K` → оверлей поиска (§9.3); маскот → раскрывает активный прогон (§3); расход → Настройки/биллинг.

## 1. Карта экранов и переходов (user-flow прототипа)

```
                    ┌─────────┐
                    │  Обзор  │◀── вход после логина
                    └────┬────┘
        ┌───────┬────┬───┴───┬─────────┬──────────┬──────────┐
        ▼       ▼    ▼       ▼         ▼          ▼          ▼
   ┌────────┐ ┌─────┐ ┌────┐ ┌───────┐ ┌──────────┐ ┌────────┐
   │ Канва  │ │Данн.│ │Навы│ │Прогоны│ │Эксплуат. │ │Паспорт │
   │(сборка)│ │(рец.│ │(кат│ │(пульт)│ │ (ФЛОТ)   │ │(конв.) │
   └───┬────┘ └──┬──┘ └────┘ └───┬───┘ └────┬─────┘ └────────┘
       │         │               │          │  ┌─ Развёртывания ▸ ЖЦ (deploy/пауза/
       │  «предпросмотр рецепта»  │          │  │  отзыв/пересмотр→Канва/вывести)
       ▼         │               ▼          ├──┼─ Живые ─── клик инстанс ▸ §3 Пульт
   «Запустить агента»──────▶┌─────────────┐  │  ├─ Карта процессов
                            │ HITL-модалка│  │  └─ Здоровье ── алерт ▸ инстанс/§7
   «пересмотреть развёрн.»◀─┤  Прогоны    │  │
        (Канва: новый draft)└─────────────┘  └──▶ «развернуть» (из Паспорта/теста)
```
**Золотой путь (для демо-прототипа):** Обзор → Навыки (посмотреть навык+безопасность) → Данные (создать рецепт + предпросмотр) → Канва (собрать агента) → «Запустить» → Прогоны (живой пульт: волны/доска/аудитор) → HITL-модалка (approve) → результат + Паспорт (конверт закрыт).
**Путь эксплуатации (второй сценарий прототипа):** Паспорт → «Развернуть» → Эксплуатация/Развёртывания (реестр) → Живые (кто работает сейчас) → клик инстанс → §3 Пульт → Здоровье (алерт дрейфа) → «Пересмотреть через канву» → §6 Канва (новая версия) → «Развернуть» (откат/новый vN).

## 3. Прогоны — ПУЛЬТ (★ MVP #1, главный экран)

**Назначение:** живое наблюдение исполнения — волны, доска, эстафеты, аудитор, HITL. Здесь «снимаем чёрный ящик».

```
CONTENT (2 колонки):
┌─ H1 «Прогон: оценка идеи X» ·· 🐵думает ·· [⏸ Esc-стоп] ─┐
├──────────────────────────────────────┬──────────────────┤
│ CANVAS ВОЛН (real-time, лев. 60%)     │ ДОСКА (прав.40%)  │
│                                        │  Blackboard:      │
│  Волна 1 ▓готово   Волна 2 ▓идёт       │  ·факты           │
│  ┌ analyst ┐  ┌ finance ┐             │  ·результаты      │
│  │data_query│→│dcf-valu.│  《волны》   │  ·эстафеты        │
│  │  ✓       │  │ 🌀      │             │  [лента событий]  │
│  └──────────┘  └─────────┘             │  agent·note·time  │
│       │ handoff《эстафета-орбита》      │                   │
│  ┌ critic ┐                            ├──────────────────┤
│  │risks 🌀 │                            │ ВЕРДИКТ АУДИТОРА  │
│  └─────────┘                           │ Definition of Done│
│                                        │ ✓/✗ чеклист       │
│  progress: волна 2/3 ░░▓──             │ пробелы → [ремед.]│
├────────────────────────────────────────┴──────────────────┤
│ HITL-ПОЛОСА (если есть ожидание): 🟠 «отправить письмо?»    │
│   предпросмотр ·· [Отклонить] [Разрешить ▓]                 │
└────────────────────────────────────────────────────────────┘
```
- **Canvas волн** (OpenClaw-паттерн + брендкит): узлы = агенты (карточка семья·роль·навык), статус-иконка = маскот-состояние (готово/думает-скан/стоп); стрелки волн; **«Волны»**-лоадер на активных; **«Эстафета»**-орбита на handoff; сегмент-прогресс «волна N/M».
- **Доска** (Blackboard): лента событий (факт/результат/эстафета/claim) mono, агент+время; live-append.
- **Вердикт аудитора:** Definition of Done чеклист ✓/✗, пробелы, `[Ремедиация]` если провал.
- **HITL-полоса:** появляется при action-навыке; предпросмотр (письмо/тикет), `[Разрешить]` (primary, оптимистично + undo 5с) / `[Отклонить]` (danger → модалка причины). Наследие LUDA Пульт.
- **Данные:** `/api/runs/{id}/stream` (SSE — волны/доска live), `/api/runs/{id}/audit`, `/api/hitl/{id}`.
- **Состояния:** нет активного → «Запусти прогон» (CTA); ошибка стрима → баннер + ретрай; завершён → маскот «DoD✓», canvas замирает, итог-синтез разворачивается.
- **Кликабельность:** узел агента → поповер (навыки узла + safety + per-node модель — находка DeepSeek); `[стоп]`/Esc → подтверждение остановки; `[Разрешить]`→ оптимистично скрыть+тост-undo; `[Ремедиация]` → новая под-волна на canvas; событие доски → подсветка связанного узла.

## 5. Данные — РЕЦЕПТЫ + КОННЕКТОРЫ (★ MVP #3)

**Назначение:** no-code рецепт «источник → canonical» с **предпросмотром на реальной выборке** (Hermes preview-pane).

```
CONTENT (2 колонки):
┌─ H1 «Данные» ·· [Рецепты | Коннекторы] таб ·· [＋ рецепт] ─┐
├──────────────────────────────────┬────────────────────────┤
│ РЕДАКТОР РЕЦЕПТА (лев. 55%)        │ ПРЕДПРОСМОТР (прав.45%) │
│ source: [адаптер ▾ csv/http/      │ canonical-записи:       │
│         sqlite/computed]          │ ┌──────────────────┐   │
│  ·путь/URL/query···········       │ │{id, amount, cust…│   │
│ entity: [transaction ▾]           │ │ provenance·ttl   │   │
│ map:  поле→[col/cast/lookup]  [＋] │ └──────────────────┘   │
│ rules:[assert…][pii_mask…]    [＋] │ ✓ 500 записей          │
│ emit: schema·ttl                  │ ⚠ 12 невалидно по схеме│
│                                    │ [🌀 Сканирование >3с]  │
│         [Проверить ▓] [Сохранить] │                        │
└──────────────────────────────────┴────────────────────────┘
Таб «Коннекторы»: грид подключённых источников (csv/http/sqlite/computed) +
  [＋ подключить] · у http — бейдж «egress→анти-SSRF», у sqlite — «read-only».
```
- **Редактор:** форма (адаптер-селект, entity, map-строки поле→спека, rules-чипы, emit); всё no-code.
- **Предпросмотр:** результат `data_run` на выборке — canonical JSON + provenance/ttl; счётчики (записано/отброшено/невалидно по схеме); при долгом прогоне — **«Сканирование»**-лоадер.
- **Данные:** `/api/data/adapters`, `/api/data/schema/{entity}`, `POST /api/data/recipe/preview` (dry-run), `/api/data/recipes`, `/api/data/connectors`.
- **Состояния:** пустой рецепт → плейсхолдеры + подсказка; ошибка источника → баннер (различать «нет данных» vs «ошибка адаптера»); превью пусто → «0 записей — проверь map/rules».
- **Кликабельность:** адаптер-селект меняет поля source; `[Проверить]` → предпросмотр (не сохраняя); `[Сохранить]` → в список рецептов; таб Коннекторы → грид; `[подключить]` → модалка адаптера.

## 6. Канва — СБОРКА АГЕНТА

**Назначение:** собрать агента из семей/ролей/навыков + источников; гибрид проводной поток + LLM-узлы (миграция канвы СВОД).

```
CONTENT (3 зоны):
┌─ H1 «Сборка: Финаналитик» ·· [паспорт ▸][Запустить ▓] ──────┐
├──────────┬───────────────────────────────────┬─────────────┤
│ ПАЛИТРА   │ ХОЛСТ (поток)                     │ ИНСПЕКТОР   │
│ (лев.220) │  ┌data_query┐→┌dcf-valuation┐     │ (прав.280)  │
│ поиск🔍   │  │источник  │  │ навык·finance│    │ узел:       │
│ ▸Семьи    │  └──────────┘  └──────┬───────┘    │ роль·модель │
│  ·роли    │        ⋔ LLM-узел(ветка)           │ БЕЗОПАСНОСТЬ│
│ ▸Навыки   │              ┌───────┐             │ mode/egress │
│  семафор  │              │ вывод │             │ /cite       │
│ ▸Источники│              └───────┘             │ [слайдер    │
│ [drag→]   │  [＋ LLM-черновик потока]           │  прав]      │
└──────────┴───────────────────────────────────┴─────────────┘
```
- **Палитра:** каталог с семафор-чипами (семьи/роли/навыки/источники), drag на холст.
- **Холст:** узлы (источник/навык/LLM-решение/вывод), рёбра-поток; `[LLM-черновик потока]` — сгенерировать поток по описанию.
- **Инспектор:** свойства узла — роль, per-node модель (DeepSeek-паттерн), **безопасность + слайдер прав** (ужесточить мгновенно / ослабить → мини-аудит; макс-крит залочен — из СВОД).
- **Пересмотр развёрнутого (FR-O4):** при открытии из §8а header показывает баннер «Пересмотр развёрнутого · vN в проде»; правки создают **новый draft vN+1** (прод-версия не трогается до повторного «Развернуть»); действие `[Развернуть]` в этом режиме заменяет `[Запустить]` и ведёт в §8а с диффом версий.
- **Данные:** `/api/families`, `/api/skills`, `/api/data/adapters`, `POST /api/flow/draft` (LLM-черновик), `/api/flow/save`; для пересмотра — `GET /api/deployments/{id}` (deployed-спека → draft).
- **Состояния:** пустой холст → «Опиши агента — соберу черновик» (LLM); невалидный поток → подсветка узла + причина; режим пересмотра → баннер «vN в проде, правишь копию».
- **Кликабельность:** drag из палитры → узел; клик узла → инспектор; `[паспорт]` → §7 предпросмотр конверта; `[Запустить]` → §9.1 → §3 Пульт; **в режиме пересмотра `[Развернуть]` → §8а Развёртывания (дифф+подтверждение)**; слайдер прав → мгновенно перекрашивает семафор узла.

## 7. Паспорт — КОНВЕРТ (Governance)

## 9. Модалки и оверлеи

**9.1 Запуск прогона:** цель (textarea) + превью плана волн (детерминированная декомпозиция по семьям, редактируемо) + оценка стоимости → `[Запустить ▓]` → §3.
**9.2 HITL-подтверждение:** предпросмотр действия (письмо/тикет — рендер), провенанс, `[Разрешить ▓]`/`[Отклонить→причина]`. Оптимистично + undo 5с (LUDA-паттерн).
**9.3 ⌘K-палитра:** поиск по навыкам/агентам/прогонам/командам; Enter → переход.
**9.4 Подключение адаптера:** форма креды/URL/путь + тест-прогон.
**9.5 Развернуть агента (→ §8а):** выбор версии (vN) + участок процесса + триггер (событие Data Plane / расписание / входящая задача, ADR-025) + политика автономии (≤ контракт LUDA, залочен потолок) + лимит параллельных экземпляров → превью конверта → `[Развернуть ▓]`. Проверка «автономия ≤ контракт» — блок деплоя при превышении. Для «вывести/отзыв» — отдельные подтверждения (retire = type-to-confirm + дренаж; rollback = дифф vN↔vN-1, ADR-024).

## 10. Общие состояния (рисовать для КАЖДОГО экрана)

| Состояние | Паттерн |
|---|---|
| **Загрузка** | скелетон (форма известна — `ab-shimmer`) или спиннер-Кольцо (неизвестна) |
| **Пусто** | иконка + одна фраза + один CTA (ведёт к действию) |

| **Успех действия** | тост + оптимистичное обновление (+undo где обратимо) |

## 11. Чек-лист приёмки прототипа (каждый экран)

- [ ] Отрисован в **dark и light** темах.
- [ ] Статусы — только семафор-токены (`--ok/--warn/--crit`), не произвольный hex.
- [ ] Один **primary** на экран; focus-ring на всех интерактивах; hover/active состояния.
- [ ] Контраст WCAG AA ≥4.5:1 (особенно текст на стекле — тестировать).

- [ ] Сверено с UI-kit (`ABOP_DESIGN_KIT.md`) и брендкитом.

## 8а. Эксплуатация — ФЛОТ (Fleet / Operations)

**Назначение:** управление агентами **в проде** (не разработка) — реестр развёртываний, живые экземпляры, карта процессов, здоровье флота. Здесь governance из «проверки при сборке» становится **постоянным контролем в эксплуатации** (FR-O1..O6; ADR-022 Deployment≠Run, ADR-024 версии+откат, ADR-025 триггеры, ADR-027 governance на экземпляре).
**Референс:** Пульт (§3) для инстансов, размещение LUDA (AS-IS/TO-BE) для карты процессов.
**Приоритет отрисовки:** ПОСЛЕ MVP-экранов Run (§3→§4→§5) — флот надстраивается над рабочим одиночным прогоном.

```
CONTENT:
┌─ H1 «Эксплуатация» ·· 🟢 флот здоров ·· [＋ Развернуть] ▓ ──┐
├────────────────────────────────────────────────────────────┤
│ [Развёртывания] [Живые]•5 [Карта процессов] [Здоровье]  ← табы│
└────────────────────────────────────────────────────────────┘
```
- **Общее:** 4 таба; header-статус = семафор здоровья флота (`/api/fleet/health`); primary `[＋ Развернуть]` (модалка §9.5). Бейдж «Живые•N» дублирует sidebar-счётчик.

### Таб «Развёртывания» (FR-O1 реестр + FR-O4 ЖЦ)

```
┌─ [фильтр: статус ▾][участок ▾][владелец ▾][🔍] ·· 4 ──────────┐
├──────────────────────────────────────────────────────────────┤
│ ТАБЛИЦА-РЕЕСТР (строки = прод-агенты):                        │
│ агент·версия │ участок / триггер │статус│владел.│автон.│ЖЦ    │
│ ┌──────────────────────────────────────────────────────────┐ │
│ │Финаналитик v3│«оценка заявок»/│🟢актив│@ivan │A2 ▓ │[⋯]  │ │
│ │              │событие Data    │       │      │≤LUDA │      │ │
│ ├──────────────────────────────────────────────────────────┤ │
│ │Почта-дайджест│«входящие»/     │🟡пауза│@olga │A1   │[⋯]  │ │
│ │ v1           │расписание 09:00│       │      │     │      │ │

```
- **Компоненты:** таблица-реестр (строка = развёртывание); колонки имя·версия / участок·триггер / статус (семафор-чип актив/пауза/отозван) / владелец / автономия (A-уровень + «≤LUDA» бейдж конверта) / `[⋯]`-меню ЖЦ; фильтр-бар; primary `[＋ Развернуть]`.
- **Триггер-иконка:** событие Data Plane / расписание / входящая задача (ADR-025) — типизирована чипом.
- **ЖЦ-действия (FR-O4):** `пауза/возобновить` (мгновенно, тост+undo) · `отзыв версии` → откат к vN-1 (подтверждение + дифф, ADR-024) · `пересмотреть через канву` → §6 Канва (режим пересмотра, новый draft) · `вывести (retire)` → **type-to-confirm** модалка + индикатор дренажа живых экземпляров.
- **Данные:** `GET /api/deployments`; действия — `POST /api/deployments/{id}/deploy|pause|retire|rollback`.
- **Состояния:** пусто → «В проде пока никого · [Развернуть агента]» (CTA → §9.5); загрузка → скелетон-строки (форма таблицы известна → shimmer); ошибка → баннер `--crit` «реестр недоступен» + ретрай; наполнено → строки с семафор-статусами.
- **Кликабельность:** строка → §7 Паспорт этого агента (прод-статус развёрнут); `[⋯]` → меню ЖЦ; «пересмотреть» → §6 Канва; «вывести» → type-to-confirm модалка; «отзыв» → дифф-подтверждение; фильтры → сужают реестр.

- **Компоненты:** таблица-инстансов (строка = живой экземпляр = помеченный авто-прогон `deployment_id+instance_id`); колонки агент / что делает (шаг·навык) / инициатор (событие·человек·расписание) / длительность (тикер) / стоимость (per-instance из cost_journal) / статус = **маскот-состояние Эйп**; индикатор авто-обновления (⟳, `[пауза-обн]`).
- **Авто-обновление:** поллинг/стрим (2с); строки live-append при старте инстанса, обновление in-place, fade-out при завершении; `prefers-reduced-motion` → без fade.
- **Данные:** `GET /api/instances` (поллинг/SSE); клик → `/api/runs/{instance_run_id}/stream` (§3).
- **Состояния:** пусто → «Экземпляров сейчас нет · развёртывания ждут триггера» (не ошибка — норма); загрузка → скелетон-строки; ошибка стрима → баннер + «обновление приостановлено» + ретрай; наполнено → живые строки с маскот-статусами.
- **Кликабельность:** строка/инстанс → **§3 Пульт этого экземпляра** (волны/доска/аудитор/HITL конкретного авто-прогона); статус 🟠HITL → §9.2 HITL-модалка; статус 🔴ошибка → §3 с раскрытой ошибкой; `[пауза-обн]` → замораживает поллинг.

- **Кликабельность:** карточка агента → §7 Паспорт; счётчик экз → §8а/Живые с фильтром по агенту; пунктир-слот `[＋ посадить агента]` → §9.5 деплой на этот участок; узел HITL-точки → пояснение.

```

- **Ре-аттестация (FR-O6):** алерт дрейфа → действие `[ре-аттестация]` (стык с вкладкой Безопасность/GAPS §7 — периодический пересмотр прав прод-агента).
- **Данные:** `GET /api/fleet/health` (агрегаты + алерты + тренды).
- **Состояния:** пусто → «Флот пуст — метрик нет» (нет развёртываний); загрузка → скелетон KPI+спарклайны; ошибка → баннер + ретрай; всё зелено → «🟢 флот здоров, алертов нет».
- **Кликабельность:** KPI «Ошибки» → §8а/Живые с фильтром ошибок; KPI «В HITL» → §3 с очередью; алерт `[разбор]` → §3 Пульт инстанса с ошибкой; `[ре-аттестация]` → вкладка Безопасность (объект = развёртывание); `[Пульт]` → §3.

**Governance-инвариант (сквозной для §8а):** конверт/автономия/HITL/аудит применяются на КАЖДОМ живом экземпляре (ADR-027); превышение конверта или дрейф DoD → алерт + возможность отзыва версии (ADR-024). Автономия в реестре всегда с бейджем «≤ контракт LUDA».
