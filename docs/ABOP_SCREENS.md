# ABOP — Экранная раскладка для прототипа

**Назначение:** пошаговая раскладка каждого экрана среды ABOP, чтобы дизайнер отрисовал **точные мокапы и кликабельный прототип**. Для каждого экрана: зоны layout, компоненты (из UI-kit), состояния (пустой/загрузка/ошибка), и **кликабельность** (что нажимается → куда ведёт).
**Связка:** токены и компоненты — `ABOP_DESIGN_KIT.md`; продукт/вкладки/FR — `ABOP_PRD.md` v1.1; бренд/маскот/спиннеры — `docs/brand/`.
**Референс структуры:** LUDA MIRA v3 (сетка, вкладки-маршрут, паттерны экранов — переиспользуем, перекрашиваем в бренд ABOP).
**Статус:** v1.0. Приоритет отрисовки: **MVP = §3 Пульт → §4 Навыки → §5 Данные**, затем §2/§6/§7/§8.

Легенда зон: `▓` акцент/активное · `░` вторичное/стекло · `·` мета/mono · `[ ]` интерактив.

```

│  SIDEBAR     │  TOPBAR: крошки · ⌘K поиск ·············· [тема] [расход]  │
│  (240px)     ├──────────────────────────────────────────────────────────┤
│  ▓ лого ABOP │                                                            │
│  конверт     │                    CONTENT (макс 1280px)                   │
│              │                                                            │
│  МАРШРУТ:    │                                                            │
│  [Обзор]     │                                                            │
│  [Канва]     │                                                            │
│  [Данные]    │                                                            │
│  [Навыки]    │                                                            │
│  [Прогоны]•3 │  ← бейдж = активные прогоны / HITL в очереди               │
│  [Паспорт]   │                                                            │
│  [Настройки] │                                                            │
│              │                                                            │
│  ─────────   │                                                            │
│  🐵 Эйп      │  ← маскот-статус текущего прогона (idle/думает/HITL/…)     │
│  «думает»    │                                                            │
│  @user·роль  │                                                            │
└──────────────┴──────────────────────────────────────────────────────────┘
```
- **Sidebar** (240px, стекло на градиенте): лого-конверт вверху; вертикальный маршрут вкладок (активная — индиго-подсветка + левый бордер `--brand`); бейджи-счётчики (Прогоны•N, Паспорт при нарушении конверта — амбер/крит точка); внизу **маскот Эйп** отражает статус активного прогона + пользователь/роль.
- **Topbar**: крошки маршрута слева; `⌘K`-палитра (поиск по навыкам/агентам/прогонам); справа — переключатель темы (dark по умолчанию) и индикатор расхода (`cost_journal`: токены/₽ + остаток недельной квоты).
- **Темы:** dark-first (основная), light — по образцу двухтемности LUDA. Все состояния рисовать в обеих.
- **Адаптив:** ≥1280 полный; 1024 — sidebar сворачивается в иконки; <768 не приоритет (среда разработки — десктоп).

**Кликабельность каркаса:** каждый пункт маршрута → свой экран (§2–§8); лого → Обзор; `⌘K` → оверлей поиска (§9.3); маскот → раскрывает активный прогон (§3); расход → Настройки/биллинг.

## 1. Карта экранов и переходов (user-flow прототипа)

```
                    ┌─────────┐
                    │  Обзор  │◀── вход после логина
                    └────┬────┘
        ┌────────────┬───┴────┬────────────┬───────────┐
        ▼            ▼        ▼            ▼           ▼
   ┌────────┐  ┌────────┐ ┌───────┐  ┌─────────┐ ┌──────────┐
   │ Канва  │  │ Данные │ │Навыки │  │ Прогоны │ │ Паспорт  │
   │(сборка)│  │(рецепты│ │(катал.│  │ (пульт) │ │(конверт) │
   └───┬────┘  │+коннек)│ │+безоп)│  └────┬────┘ └──────────┘
       │        └───┬────┘ └───────┘       │
       │            │                      ▼
       │  «предпросмотр рецепта»    ┌─────────────┐

**Золотой путь (для демо-прототипа):** Обзор → Навыки (посмотреть навык+безопасность) → Данные (создать рецепт + предпросмотр) → Канва (собрать агента) → «Запустить» → Прогоны (живой пульт: волны/доска/аудитор) → HITL-модалка (approve) → результат + Паспорт (конверт закрыт).

## 3. Прогоны — ПУЛЬТ (★ MVP #1, главный экран)

**Назначение:** живое наблюдение исполнения — волны, доска, эстафеты, аудитор, HITL. Здесь «снимаем чёрный ящик».

```
CONTENT (2 колонки):
┌─ H1 «Прогон: оценка идеи X» ·· 🐵думает ·· [⏸ Esc-стоп] ─┐
├──────────────────────────────────────┬──────────────────┤
│ CANVAS ВОЛН (real-time, лев. 60%)     │ ДОСКА (прав.40%)  │
│                                        │  Blackboard:      │
│  Волна 1 ▓готово   Волна 2 ▓идёт       │  ·факты           │
│  ┌ analyst ┐  ┌ finance ┐             │  ·результаты      │
│  │data_query│→│dcf-valu.│  《волны》   │  ·эстафеты        │
│  │  ✓       │  │ 🌀      │             │  [лента событий]  │
│  └──────────┘  └─────────┘             │  agent·note·time  │
│       │ handoff《эстафета-орбита》      │                   │
│  ┌ critic ┐                            ├──────────────────┤
│  │risks 🌀 │                            │ ВЕРДИКТ АУДИТОРА  │
│  └─────────┘                           │ Definition of Done│
│                                        │ ✓/✗ чеклист       │
│  progress: волна 2/3 ░░▓──             │ пробелы → [ремед.]│
├────────────────────────────────────────┴──────────────────┤
│ HITL-ПОЛОСА (если есть ожидание): 🟠 «отправить письмо?»    │
│   предпросмотр ·· [Отклонить] [Разрешить ▓]                 │
└────────────────────────────────────────────────────────────┘
```
- **Canvas волн** (OpenClaw-паттерн + брендкит): узлы = агенты (карточка семья·роль·навык), статус-иконка = маскот-состояние (готово/думает-скан/стоп); стрелки волн; **«Волны»**-лоадер на активных; **«Эстафета»**-орбита на handoff; сегмент-прогресс «волна N/M».
- **Доска** (Blackboard): лента событий (факт/результат/эстафета/claim) mono, агент+время; live-append.
- **Вердикт аудитора:** Definition of Done чеклист ✓/✗, пробелы, `[Ремедиация]` если провал.
- **HITL-полоса:** появляется при action-навыке; предпросмотр (письмо/тикет), `[Разрешить]` (primary, оптимистично + undo 5с) / `[Отклонить]` (danger → модалка причины). Наследие LUDA Пульт.
- **Данные:** `/api/runs/{id}/stream` (SSE — волны/доска live), `/api/runs/{id}/audit`, `/api/hitl/{id}`.
- **Состояния:** нет активного → «Запусти прогон» (CTA); ошибка стрима → баннер + ретрай; завершён → маскот «DoD✓», canvas замирает, итог-синтез разворачивается.
- **Кликабельность:** узел агента → поповер (навыки узла + safety + per-node модель — находка DeepSeek); `[стоп]`/Esc → подтверждение остановки; `[Разрешить]`→ оптимистично скрыть+тост-undo; `[Ремедиация]` → новая под-волна на canvas; событие доски → подсветка связанного узла.

## 5. Данные — РЕЦЕПТЫ + КОННЕКТОРЫ (★ MVP #3)

**Назначение:** no-code рецепт «источник → canonical» с **предпросмотром на реальной выборке** (Hermes preview-pane).

```
CONTENT (2 колонки):
┌─ H1 «Данные» ·· [Рецепты | Коннекторы] таб ·· [＋ рецепт] ─┐
├──────────────────────────────────┬────────────────────────┤
│ РЕДАКТОР РЕЦЕПТА (лев. 55%)        │ ПРЕДПРОСМОТР (прав.45%) │
│ source: [адаптер ▾ csv/http/      │ canonical-записи:       │
│         sqlite/computed]          │ ┌──────────────────┐   │
│  ·путь/URL/query···········       │ │{id, amount, cust…│   │
│ entity: [transaction ▾]           │ │ provenance·ttl   │   │
│ map:  поле→[col/cast/lookup]  [＋] │ └──────────────────┘   │
│ rules:[assert…][pii_mask…]    [＋] │ ✓ 500 записей          │
│ emit: schema·ttl                  │ ⚠ 12 невалидно по схеме│
│                                    │ [🌀 Сканирование >3с]  │
│         [Проверить ▓] [Сохранить] │                        │
└──────────────────────────────────┴────────────────────────┘
Таб «Коннекторы»: грид подключённых источников (csv/http/sqlite/computed) +
  [＋ подключить] · у http — бейдж «egress→анти-SSRF», у sqlite — «read-only».
```
- **Редактор:** форма (адаптер-селект, entity, map-строки поле→спека, rules-чипы, emit); всё no-code.
- **Предпросмотр:** результат `data_run` на выборке — canonical JSON + provenance/ttl; счётчики (записано/отброшено/невалидно по схеме); при долгом прогоне — **«Сканирование»**-лоадер.
- **Данные:** `/api/data/adapters`, `/api/data/schema/{entity}`, `POST /api/data/recipe/preview` (dry-run), `/api/data/recipes`, `/api/data/connectors`.
- **Состояния:** пустой рецепт → плейсхолдеры + подсказка; ошибка источника → баннер (различать «нет данных» vs «ошибка адаптера»); превью пусто → «0 записей — проверь map/rules».
- **Кликабельность:** адаптер-селект меняет поля source; `[Проверить]` → предпросмотр (не сохраняя); `[Сохранить]` → в список рецептов; таб Коннекторы → грид; `[подключить]` → модалка адаптера.

**Назначение:** собрать агента из семей/ролей/навыков + источников; гибрид проводной поток + LLM-узлы (миграция канвы СВОД).

│ ▸Семьи    │  └──────────┘  └──────┬───────┘    │ роль·модель │
│  ·роли    │        ⋔ LLM-узел(ветка)           │ БЕЗОПАСНОСТЬ│
│ ▸Навыки   │              ┌───────┐             │ mode/egress │
│  семафор  │              │ вывод │             │ /cite       │
│ ▸Источники│              └───────┘             │ [слайдер    │
│ [drag→]   │  [＋ LLM-черновик потока]           │  прав]      │
└──────────┴───────────────────────────────────┴─────────────┘
```
- **Палитра:** каталог с семафор-чипами (семьи/роли/навыки/источники), drag на холст.
- **Холст:** узлы (источник/навык/LLM-решение/вывод), рёбра-поток; `[LLM-черновик потока]` — сгенерировать поток по описанию.
- **Инспектор:** свойства узла — роль, per-node модель (DeepSeek-паттерн), **безопасность + слайдер прав** (ужесточить мгновенно / ослабить → мини-аудит; макс-крит залочен — из СВОД).
- **Данные:** `/api/families`, `/api/skills`, `/api/data/adapters`, `POST /api/flow/draft` (LLM-черновик), `/api/flow/save`.
- **Состояния:** пустой холст → «Опиши агента — соберу черновик» (LLM); невалидный поток → подсветка узла + причина.
- **Кликабельность:** drag из палитры → узел; клик узла → инспектор; `[паспорт]` → §7 предпросмотр конверта; `[Запустить]` → §9.1 → §3 Пульт; слайдер прав → мгновенно перекрашивает семафор узла.

## 9. Модалки и оверлеи

**9.1 Запуск прогона:** цель (textarea) + превью плана волн (детерминированная декомпозиция по семьям, редактируемо) + оценка стоимости → `[Запустить ▓]` → §3.
**9.2 HITL-подтверждение:** предпросмотр действия (письмо/тикет — рендер), провенанс, `[Разрешить ▓]`/`[Отклонить→причина]`. Оптимистично + undo 5с (LUDA-паттерн).
**9.3 ⌘K-палитра:** поиск по навыкам/агентам/прогонам/командам; Enter → переход.
**9.4 Подключение адаптера:** форма креды/URL/путь + тест-прогон.

---

## 10. Общие состояния (рисовать для КАЖДОГО экрана)

| Состояние | Паттерн |
|---|---|
| **Загрузка** | скелетон (форма известна — `ab-shimmer`) или спиннер-Кольцо (неизвестна) |
| **Пусто** | иконка + одна фраза + один CTA (ведёт к действию) |
| **Ошибка** | баннер `--crit`, различать «нет данных» vs «сбой» + ретрай |
| **Долгое ожидание >3с** | «Сканирование»-лоадер + поясняющий текст (что делает) |
| **Успех действия** | тост + оптимистичное обновление (+undo где обратимо) |

## 11. Чек-лист приёмки прототипа (каждый экран)

- [ ] Отрисован в **dark и light** темах.
- [ ] Статусы — только семафор-токены (`--ok/--warn/--crit`), не произвольный hex.
- [ ] Один **primary** на экран; focus-ring на всех интерактивах; hover/active состояния.
- [ ] Контраст WCAG AA ≥4.5:1 (особенно текст на стекле — тестировать).
- [ ] Все 4 состояния (загрузка/пусто/ошибка/наполнено) нарисованы.
- [ ] `prefers-reduced-motion` — упрощённый мотив-кит (важно: анимаций много).
- [ ] Кликабельность: каждый `[интерактив]` ведёт в указанный экран/модалку (для прототипа).
- [ ] Маскот Эйп отражает корректное состояние прогона.
- [ ] Сверено с UI-kit (`ABOP_DESIGN_KIT.md`) и брендкитом.
